jni_surface_godot.txt -- the JNI surface of the engine this wrapper drives.

Generated from the Super Mario 127 0.9.1 APK's lib/arm64-v8a/libgodot_android.so
(Godot 3.6.stable.official) and its classes.dex. Regenerate with
tools/dump_jni_surface.sh <apk>.

This is the contract main.c, nx_input.c, jni_helpers.c and swkbd_shim.c code
against: a name missing from section 1 means the engine build differs from the
one these were written for, and so_try_find_addr_rx returns 0 for it.

== 3. Differences from Godot 3.5.2 (why this wrapper refuses 3.5) ==

  gone in 3.6      GodotLib.touch__IIII_3F        overloaded touch(), 3 exports
                   GodotLib.touch__IIII_3FI
                   GodotLib.touch__IIII_3FIFF
                   GodotLib.hover
                   GodotLib.doubleTap
                   GodotIO.showKeyboard(Ljava/lang/String;ZIII)V

  new in 3.6       GodotLib.dispatchTouchEvent    (III[FZ)V   -- nx_input.c
                   GodotLib.dispatchMouseEvent    (IIFFFFZZ)V -- unused; the
                                                  controller cursor synthesises
                                                  mouse events inside Godot
                   GodotLib.magnify / pan         gesture input, unused
                   GodotLib.ttsCallback           TTS, unused
                   GodotLib.getEditorSetting      editor only, unused
                   GodotIO.showKeyboard(Ljava/lang/String;IIII)V
                                                  bool multiline -> int type
                   GodotTTS.*                     speak/isSpeaking/isPaused/
                                                  pauseSpeaking/resumeSpeaking/
                                                  stopSpeaking/getVoices

  changed in 3.6   GodotLib.setup  ([Ljava/lang/String;)V
                                -> ([Ljava/lang/String;Lorg/godotengine/godot/tts/GodotTTS;)Z

  unchanged        GodotLib.initialize -- still (Activity, Godot, AssetManager,
                   GodotIO, GodotNetUtils, DirectoryAccessHandler,
                   FileAccessHandler, boolean)

TTS_Android::setup() only caches method IDs off the GodotTTS object, so
jni_fake.c's g_tts needs to exist but never has to answer a call unless the
game uses OS.tts_* -- SM127 does not.
